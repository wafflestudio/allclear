# ADR-0001: 일회용 링크 기반 동아리 관리자 권한 이전

- 상태: Accepted
- 날짜: 2026-08-24
- 관련 문서: [동아리 관리자 권한 이전 아이디어](../ideas/club-manager-transfer.md)

## 배경

동아리에는 활성 관리자가 한 명만 존재한다. 기존 관리자가 운영자 도움 없이 다른 올클 회원에게 권한을 넘길 수 있어야 하며, 이전 도중 권한 공백·중복 관리자·링크 재사용이 발생해서는 안 된다. 대상 회원을 사전에 검색하는 방식은 개인정보 노출과 별도 검색 UX를 만들기 때문에 이번 범위에서 제외했다.

## 결정

기존 관리자가 72시간 동안 유효한 일회용 링크를 발급하고, 링크를 연 최초의 로그인 회원이 동아리 이름을 확인한 뒤 수락하는 방식을 사용한다.

- 토큰은 256비트 난수로 만들고 URL에만 노출한다. 데이터베이스에는 SHA-256 해시만 저장한다.
- 같은 동아리에서 링크를 재발급하면 사용되지 않은 기존 링크를 폐기한다.
- 만료·폐기·사용된 링크는 동일한 404 응답으로 숨기며, 자기 자신에게 이전하려는 요청은 409로 거절한다.
- 수락 트랜잭션은 현재 관리자와 초대를 같은 순서로 잠근 뒤 기존 관리자 soft delete, 새 관리자 생성, 초대 사용 처리, 기존 관리자 알림 생성을 한 번에 수행한다.
- 부분 유니크 인덱스로 동아리별 활성 관리자 한 명과 동아리별 미사용 초대 한 개를 보장한다.
- 동일한 수락자가 성공 응답을 잃고 재요청하는 경우에는 멱등 성공을 반환한다. 다른 사용자의 재사용 시도는 404로 처리한다.
- 기존 관리자에게는 인앱 알림을 제공하며, 푸시 알림은 후속 범위로 둔다.

## 대안

### 대상 계정 사전 지정

잘못 전달된 링크의 위험은 줄지만 회원 검색·식별·개인정보 정책이 추가로 필요하다. 이번 MVP에서는 외부 메신저로 신뢰하는 대상에게 링크를 직접 전달하는 흐름을 채택했다.

### 기존 관리자의 최종 승인

양쪽 확인은 안전해 보이지만 기존 관리자가 다시 접속하지 않으면 인계가 완료되지 않는다. 즉시 이전이라는 목표와 맞지 않아 선택하지 않았다.

### 복수 관리자와 역할 모델

권한 공백 문제를 구조적으로 줄일 수 있지만 기존 단일 관리자 정책, 권한 검사, 관리 UI 전체를 바꾸는 별도 기능이다.

## 결과와 제약

- 링크를 가진 로그인 회원은 누구나 수락할 수 있으므로 기존 관리자는 신뢰하는 대상에게만 링크를 전달해야 한다.
- 링크 원문은 서버 로그와 오류 메시지에 남기지 않는다.
- 새 관리자의 관리자 표시 정보는 로그인 프로필의 이름·전화번호·입학 연도만 사용한다. 별도 학번 입력은 받지 않는다.
- 웹 링크가 앱으로 열리려면 Android App Link와 iOS AASA가 배포 도메인에서 함께 제공되어야 한다.
- 실시간/푸시 알림이 없으므로 기존 관리자는 마이페이지 진입 또는 앱 포커스 갱신 시 완료 알림을 확인한다.

## 배포 순서와 검증

1. 운영 DB에서 동아리별 활성 관리자가 둘 이상인 데이터가 없는지 마이그레이션 preflight로 확인한다.
2. `260824_club_manager_transfer.sql`을 적용한다. preflight가 실패하면 데이터를 먼저 정리하고 재실행한다.
3. 웹 API와 AASA 파일을 배포한다.
4. 모바일 앱을 배포하고 iOS/Android 실기기에서 운영·개발 도메인의 링크 진입을 각각 검증한다.
5. 발급, 재발급, 만료, 자기 이전, 두 사용자 동시 수락, 성공 응답 유실 후 재시도, 기존 관리자 알림을 QA한다.

마이그레이션 롤백 SQL은 파일 하단에 기록한다. 다만 새 기능 사용 후 롤백하면 이미 완료된 관리자 변경 자체는 자동으로 되돌리지 않는다.
