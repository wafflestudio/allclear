# 동아리 관리자 권한 이전

## Problem Statement

현재 동아리 관리자가 운영자 개입 없이, 권한 공백이나 중복 관리자 없이, 신뢰하는 회원에게 관리 권한을 안전하게 이전하려면 어떻게 해야 하는가?

## Recommended Direction

기존 관리자가 72시간 유효한 일회용 링크를 발급하고, 링크를 받은 최초의 로그인 회원이 동아리 정보를 확인한 뒤 수락하면 권한을 즉시 교체한다. 재발급 시 기존 링크는 폐기하고, 자기 자신 수락과 이미 사용·만료된 링크는 거절한다.

서버는 토큰 원문 대신 해시를 저장한다. 수락 시 초대와 현재 관리자 행을 잠근 하나의 트랜잭션 안에서 기존 권한 해제, 새 권한 생성, 초대 사용 처리를 수행한다. DB는 동아리별 활성 관리자 1명 제약을 보장한다.

## Key Assumptions to Validate

- [ ] 72시간 안에 대부분의 인계가 끝난다 — QA/운영 시나리오와 실제 사용 로그로 확인
- [ ] 외부 메신저 링크가 앱의 수락 화면까지 안정적으로 연결된다 — iOS/Android 실기기 검증
- [ ] 운영 DB에 활성 중복 관리자 데이터가 없다 — 배포 전 SQL 점검
- [ ] 새 관리자는 올클 로그인 회원이다 — 비로그인 진입 시 로그인 후 원래 링크로 복귀하는 흐름 검증

## MVP Scope

- 기존 관리자: 이전 확인, 링크 발급·복사, 복사 완료
- 새 관리자: 링크 조회, 로그인 유도, 권한 받기, 성공 안내
- 기존 관리자: 이전 완료 인앱 알림
- 백엔드: 발급·조회·수락 API, 72시간 만료, 재발급 폐기, 원자적 교체
- DB: 이전 초대 테이블, 활성 관리자 유일성 제약, 필요한 알림 타입
- 모바일: 딥링크 경로, Figma 7개 상태, 캐시/권한 갱신
- 테스트: 성공, 자기 이전, 만료, 재사용, 재발급, 동시 수락, 무권한 발급

## Not Doing (and Why)

- **이중 확인** — 기존 관리자 재접속 의존성이 인계를 막을 수 있음
- **대상 계정 사전 지정** — 사용자 검색과 개인정보 UX가 별도 문제임
- **예약 이전·되돌리기** — 핵심 가정 검증에 불필요함
- **복수 관리자·역할 체계** — 데이터 모델과 권한 정책이 다른 대형 기능임
- **이전 이력 UI** — 서버 감사 데이터는 남기되 사용자 화면은 후속으로 미룸
- **푸시 알림** — 현재 인앱 알림 체계를 먼저 활용함
